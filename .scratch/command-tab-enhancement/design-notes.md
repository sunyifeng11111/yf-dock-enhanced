# Command+Tab 增强：设计访谈

2026-10-16，用户已完成四轮需求访谈，并在整体复核后回复“确认”。以下规则已确认为第一版产品范围，已整理为同目录的[正式规格](spec.md)。尚未开始实现，也未完成新功能的运行验证。

## 已确认

2026-10-16，第一轮回答：Q1、Q3 接受推荐；Q2 调整为默认开启，其余接受推荐。

- 按窗口切换：每个窗口一张卡片，跨应用平铺，同一应用的多个窗口分别显示，浏览器标签页不独立列出。
- 包含最小化窗口，选中并确认切换后恢复对应窗口。
- 启用增强时替代系统 Command+Tab；关闭后恢复系统行为。
- 增加独立的增强开关，与悬停预览、点击收起／恢复分别控制。
- 默认开启，包括升级后尚未设置过该独立开关的用户。
- 视觉延续现有小预览窗的玻璃／毛玻璃背景、圆角、字体、缩略图比例和短暂动效。
- 卡片包含应用图标和窗口标题；键盘选中态使用清楚的中性明暗底色。
- 面板居中展示，窗口多时允许多行排列。

2026-10-16，第二轮回答：Q4、Q5、Q6 均接受推荐。

- 按住 Command 时，Tab 向前选择，Shift+Tab 反向选择；松开 Command 才确认切换。
- 浏览卡片只改变选中项，不提前激活或恢复窗口；确认时才恢复最小化窗口。
- Esc 取消选择，保持原窗口。
- 跨应用按窗口最近使用顺序排列，同一应用的不同窗口分别记录；首次按 Command+Tab 默认选中上一个窗口，支持快速往返切换。
- 一次选择过程中保持顺序固定；最小化窗口按其原有使用顺序排列。
- 目标范围为系统能够识别的正常应用窗口，包括其他桌面、其他显示器、全屏窗口及隐藏应用的窗口。
- 确认切换后让目标窗口可见并获得焦点；跨桌面及全屏的可靠性仍待可行性验证，不能视为现有能力。

2026-10-16，第三轮回答：Q7、Q8、Q9、Q10 均接受推荐。

- 支持方向键按卡片位置移动选中项，Enter 立即确认。
- 鼠标移动到卡片时可选中，点击立即确认；面板出现时静止的鼠标不改变键盘选中项。
- Esc 或点击面板外取消。
- 面板显示于当前操作窗口所在屏幕中央；没有前台窗口时使用鼠标所在屏幕，一次选择过程中位置不变。
- 根据屏幕可用空间排列多行，保持卡片清晰可辨，超出部分纵向滚动；键盘选中项自动滚入可见区域。
- Tab 在最后一项与第一项之间循环，反向选择同理。
- 列出正常应用窗口和需要单独操作的对话框；排除菜单、提示气泡、桌面及内部辅助窗口。
- 不列出已运行但没有窗口的应用，例如关闭了所有窗口的 Safari；用户仍可通过 Dock 打开它。

2026-10-16，第四轮回答：Q11、Q12、Q13、Q14、Q15、Q16 均接受推荐。

- 快速按下并松开 Command+Tab 时直接切换，不闪出面板；持续按住约 0.12 秒后才显示面板。按住 Tab 时遵循系统按键重复节奏连续选择。
- 不等待截图完成：先展示应用图标和窗口标题，再补上可用缩略图。
- 最小化窗口显示最近缓存画面，并以低调文字标注“已最小化”；无缓存则显示应用图标和标题。
- 截图只存内存，没有屏幕录制权限时仍可用图标和标题切换；录屏权限撤销后清除截图缓存。
- 缺少辅助功能权限或无法接管快捷键时保留系统 Command+Tab，并在设置中说明原因；本轮选择过程中失去必要权限则取消本轮，避免误切换。
- 使用历史只在本次工具运行期间记录，不将窗口标题和使用记录写入磁盘。
- 启动时当前窗口排在首位，其余没有使用历史的窗口按应用名、窗口标题稳定排列；随后以实际使用顺序为准，仅浏览卡片不改变历史。
- 面板打开期间，关闭的窗口移除；若正被选中则顺延选择。新窗口在下次打开面板时加入。
- 没有候选窗口时取消，只有当前窗口时保持原状；恢复失败时给简短提示，不擅自切换到其他窗口。
- 用户进行新操作后，不通过延迟激活抢回焦点。
- 设置保留“Dock 功能”和“通用”，新增“窗口切换”页，提供默认开启的“Command+Tab 增强”开关及操作说明；菜单栏同步提供开关。
- 第一版固定上述交互规则，不提供自定义快捷键、延迟或卡片尺寸等选项。

## 进入实现前需要验证的事实

实现期间的更新：2026-10-16，已通过真实夹具验证隐藏／最小化恢复及已识别窗口的普通／全屏双向可见切换。冷启动子进程确认，应用已全屏时 macOS 可能只提供全屏窗口，省略此前未识别的普通窗口。用户明确回复“接受此边界并明确说明”；正式规格已补充该第一版边界与先退出全屏识别窗口的使用方式。其余验证矩阵仍按实际证据记录，不据此声明所有系统环境均已通过。

- 跨桌面、跨显示器、全屏以及隐藏应用中的指定窗口，是否能可靠枚举并激活；尤其是同一应用的不同桌面窗口。
- Command+Tab 能否稳定接管；监听失效、安全输入及修饰键松开事件丢失时，能否取消会话并恢复后续系统快捷键使用。
- 全局窗口清单、最近使用顺序及缩略图加载，是否能满足快速切换的响应要求。
- 关闭“悬停预览”但保留增强功能时，窗口枚举和截图是否独立工作；关闭某项功能不能误清除其他仍启用功能所需的状态。
- 鼠标、按键选择和最小化恢复期间，旧有“键盘活动取消延迟恢复”的逻辑是否与本次确认操作协调。

以上是待验证的技术条件，不代表用户尚未决定产品行为。若验证失败导致需要改变已确认范围，应带着具体证据重新确认。

## 现有实现事实

- `PreviewPanel.swift` 已有单应用横向缩略图卡片与玻璃／毛玻璃背景，尚无键盘选中态。
- `Accessibility.swift` 已有枚举窗口、恢复最小化窗口和激活指定窗口的逻辑；当前只记录每个应用最近使用的一个窗口，没有跨应用的全局窗口使用顺序。
- `DockService.swift` 当前仅观察键盘活动并透传事件，未接管 Command+Tab；旧有键盘活动取消延迟恢复的逻辑需要在实现新操作流程时协调。
- 缩略图仅缓存于内存；最小化窗口不生成新截图，无缓存时使用应用图标。
- 当前没有明确的桌面归属过滤与跨桌面切换策略，多显示器和第三方应用兼容性仍需验证。
- 现有服务以辅助功能权限为启动条件，未获得屏幕录制权限时仍可显示图标和标题；现有代码不会因录屏权限撤销主动清空缓存，新规则需要补齐。
- 当前两个独立功能都关闭时停止服务，新增强开关需要参与独立启停与状态展示。
- 当前设置和 README 表述为不读取具体按键，新增快捷键识别及面板导航后需要准确更新说明；不记录输入文字。
